## 核心方法

**1. Uni-Match** — 一个 actor-critic, 观测拼接任务描述 (运动模式 d + 速度/转向指令 v)。训练时每个 episode 随机采样一个模式, 并在 episode 内按固定时序重采样模式, 让策略学会"模式切换瞬间的连续响应"。关键点: 模式是**观测条件**, 不是独立策略; 模式切换处在训练中被显式覆盖, 策略学会平滑过渡而非重启。

**2. so(100) Generalist** — 技能空间参数化为若干连续/离散参数 (含步态类型、参数量), 与速度指令一同进观测; 单策略用 (skill, cmd) 条件化输出。学到的收益: 不同技能共享"感知→平衡"底层表征, 切换代价低 (表征连续)。

**3. Wheel-Legged-Lab / TITA** — 轮腿机器人按 (状态机 × 阶段) 管理 平衡/行走/跳跃: 每个模式有独立激励与控制目标, 模式间用状态机+滞回 (hysteresis) 切换, 避免临界区抖动。

**4. classic LQR 切换** — 工程惯例: 平衡控制器与行进控制器并存, 切换用滞回阈值 (进入/退出阈值不同) + 切换时刻状态变量连续 (角动量/轮速对齐), 防止切换瞬间受击。

## 可借鉴点 (映射到 xqrobotwl)

| 思路 | 落地 |
|------|------|
| 模式作为观测命令通道 (Uni-Match/so100) | commands 4D→5D: [vx,vy,vyaw,tsk, **mode**], mode∈{0站立,1点足}; obs 加 mode 维 |
| 训练时 episode 内随机重采样模式 (Uni-Match) | DR provider 对 mode 按 3~8s 随机驻留重采样, 覆盖"按键切换"各种时刻 |
| 奖励按命令条件路由 (CaT) | 奖励字典按 mode 门控: mode=0 用站立套件 (walk_flat 风格), mode=1 用相位抬腿套件; 共用 tracking/高度/直立/平滑项 |
| 滞回 + 状态连续 (LQR 工程) | 切换不重置 phase 时钟/状态; 播放层可加切换滞回 (进入抬腿 mode∈[0.8,1], 退出 <0.2) |
| 技能共享底层表征 (so100) | 单策略两模式共享网络, 课程先分练后混合, 降低多目标冲突 |

## 与我们的差异

- Uni-Match/so100 的主场景是运动库多技能 (跑/跳/蹲/匍匐), 我们的双模式是**同一行走通道上的行为调制** (站立微动 ⇄ 抬腿步态), 复杂度低一个量级, 不需要技能 embedding 空间。
- Wheel-Legged-Lab 用 FSM 状态机切模式 (模式=离散状态), 我们是 **RL 策略内部响应命令通道**, 更符合已有 toe_walk 架构。
- 轮腿双轮在"站立"下本质是倒立摆平衡 (轮速微调), 与 walking 共享轮执行器, 模式切换主要在**腿的激励**上, 不存在构型切换, 切换成本低。

## 落地建议

1. **主方案**: 单策略 + commands 5D mode 通道 + 按 mode 门控奖励 + 课程 (站立→抬腿→混合切换) + play_interactive H 键写 mode。
2. **对照/兜底**: 若混合训练冲突 (证伪: 历史课程 ramp 过陡崩溃), 退化为"奖励加权两模式联合"或"两策略+运行时切换" (不推荐, 状态不连续)。
3. **验收**: 模式内达标 (站立 §1.4 / 抬腿交替对称 §7.3) + 切换过程 0.5s 不跌倒 + 1s 内进入新模式行为, 出确定性 CSV + 渲染视频。
