## 根因 (最终定位)

**控制方向反了**: 我的 `a[6] = -w_c/wsa` 映射下 w_c>0 是**前驱** (L轮正转), 但机器人恢复前倾需要**后驱** (L轮负转)。

**决定性方向测试** (标准 env 路径, 前倾扰动 +0.1 rad):
| w_cmd | 倾角变化 | 结论 |
|---|---|---|
| +3 (前驱) | +0.10 → +0.34 ✗加重 | 前驱错误 |
| **-3 (后驱)** | **+0.10 → +0.08 ✓恢复** | **后驱正确** |
| +6 (前驱) | +0.10 → +0.45 ✗ | 更错 |
| -6 (后驱) | +0.10 → -0.07 ✓ | 恢复 |

**之前全部失败的原因**: 所有测试 (LQR/MPC/串级/扭矩/增益) 都用前驱方向 (正 kth), 让前倾加重 → 看似"物理权威不足", 实则是**正反馈**。

**为什么早期方向测试被误导**: 扭矩路径的方向测试 (前驱→前倾) 与轮子符号混淆, 加上轮子悬空 (base_z 错) 的干扰, 未能分离出"后驱才是正确方向"。

## 修复后的工作配置 (标准 env, 速度伺服)

```
w_cmd = -(kth·th + kthd·thd + kv·v + kx·xpos)   # ★ 负方向: 前倾→后驱
a[6] = -w_cmd/wsa; a[7] = w_cmd/(-wsa)            # 轮动作映射 (L 负/R 正 = 同向前驱)
腿: LEG_TARGETS_COMPENSATED = [0.02,0.15,-0.30,0,-0.18,0.28]
平滑: w_c = α·w_prev + (1-α)·w_cmd,  α=0.85      # ★ 平滑关键: 无平滑→轮命令突变激发 yaw 46°
```

**最佳增益**: K=[100, 20, 80, 30], α=0.85
**已固化进 controller.py**: 方向修正 + 直接轮速命令(不积分) + L轮翻转 + 平滑。

## 过程中发现并修复的其他 bug (均真实)

1. **轮子方向** (扭矩路径): 镜像轴应 左轮-τ/右轮+τ, 曾同号 → 扭转。
2. **初始 base_z 偏高**: 髋 pivot 在 base 原点下 8mm, base_z=0.518 让右轮离地 13mm → 视频"飞起来"。修正 0.512 (双轮着地)。
3. **渲染状态错位**: `get_physics_state()` 有前导元素 (phy[0]=0), 记录 `[t,*phy]` 导致 qpos 错位一位 → 视频机器人在地下/乱姿态。修正为 `[t,*phy[1:]]`。

## 经验教训 (用户推动的)

- **不要说"不行", 要系统性找问题** — 前一轮误判为"物理权威不足"是错的方向。
- 方向符号是轮控第一检查项: 用干净的扰动-响应测试确定, 不要被拟合/直觉误导。
- 每个渲染异常 (飞/地下) 都可能是记录/状态 bug, 先查数据再下结论。
