## 关键发现 (数据)

### 1. 腿塌陷根因 + 修复 (已解决)
- 命令 standing_angles (膝 -0.079) 时, kp=60 位置伺服在负重下**膝部下垂 ~0.22 rad** → 实际关节 +0.14, 腿塌陷机器人倒下 (0.12s)。
- **RL 策略稳态实测**: 命令 L_knee=-0.30/R_knee=+0.28 才使实际关节 = 自然站姿 (-0.076/+0.066)。
- **修复**: 用下垂补偿后的腿伺服目标 `LEG_TARGETS_COMPENSATED=[0.02,0.15,-0.30,0,-0.18,0.28]` → 腿稳住 (base_z 0.52, 膝 -0.10)。**腿问题解决。**

### 2. 平衡控制: 线性 LQR/MPC 无法稳定 (未解决, 根因已定位)
| 控制器 | 保持时间 | 说明 |
|---|---|---|
| 无控制 (腿补偿) | ~0.95s | 纯不稳定, α≈23 (θ 0→1 rad / ~1s) |
| LQR (解析模型 α25 β-2.5) | ~0.3-0.6s | 漂移/过冲 |
| 串级 PD (single_leg 结构) | ~0.95s | 各种增益 ~0.94-0.97s 上限 |
| RL 提取线性律 (20θ-4θ̇+20v) | ~0.6s | 无法复现 RL 的非线性 |
| RL 提取 + 重平滑 (α0.9) | ~1.07s | 最好的线性 |
| 系统辨识 (RL 闭环数据拟合 A,B) + LQR | ~0.1s | 闭环辨识有偏 |
| **RL 完整策略 (对照)** | **15s+** | 非线性 + 富 obs + 平滑 |

### 3. 根因分析
1. **轮速伺服 (kv=1) 极弱**: 命令轮速 5 rad/s 时实际才到 3.5, 机器人线速度仅 0.018 m/s (加速滞后)。模型 `v̇=u` 假设轮子有完美加速度权威, 实际严重不符。
2. **机器人加速滞后**: 轮子先转, 机器人惯性滞后追 — 植物有显著一阶滞后, 线性模型失真。
3. **RL 控制是非线性的**: 并排对比显示 RL 在瞬态命令 ±9 rad/s 振荡 (欠阻尼), 且 thd 反馈符号随状态变化 — 简单线性律无法复现。
4. **腿/轮耦合**: 轮子推机器人时腿载荷变化 → 腿目标需动态调整 (RL 策略实时调腿)。

**结论**: 标准 scene_flat.xml (速度伺服轮) 上, 两轮平衡是一个对线性控制器非常困难的非线性控制问题 — 这正是项目用 RL 的原因 (RL 策略训了数千轮)。

## 扭矩作动器路径 (scene_flat_vmc.xml) — 也失败, 证实根本性结论

**用户决策**: 改用轮扭矩作动器 (motor 轮 ±10N·m, 教科书 Segway LQR)。

**结果**: 扭矩 LQR (腿软件 PD kp=800 稳姿态 + 轮扭矩 LQR) 与速度伺服一样,**保持 ~0.6-1.0s** (初测 4.4s 为时间记账错误: 每步 mj_step 0.001s 但按 0.005s 计)。

**新证据**:
- 干净开环 β=3.04 (τ=1→θ̈), δ=0.996 (τ→ẍ) — 模型可用, 但闭环中真实控制效果远弱于模型 (θ̈ 模型预测 -28, 实测 +0.5) → **耦合/腿动态未建模**。
- 开环系统辨识失败 (机器人跌倒太快, 激励被失稳淹没)。
- 直接增益搜索 (正 v/位置反馈, 仿 RL) 同样 ~0.6s。
- RL 策略用 **协调的腿+轮** 平衡 (腿扭矩 ±50N·m, 是轮的 5 倍), 轮子单独不足以平衡。

## 文献方法论对照 (用户问题: 论文怎么用 LQR/MPC 平衡?)

**文献标准做法** (多篇论文一致):
1. 建模 = 两轮倒立摆, **控制输入 = 轮扭矩** u=[T_L,T_R] (DC/步进电机直接扭矩, 非速度伺服)
2. 小倾角平衡点线性化 → (A,B), 用**实测物理参数** (质量/惯量/CoM/轮半径)
3. 全状态反馈 u=-K·x, 状态含 [θ,θ̇,x,ẋ,ψ,ψ̇], Riccati 解 K; 加积分增广做零稳态误差
4. 硬件: IMU+编码器测全状态, 轮扭矩权威足够抵消重力矩

**对照本项目机器人**:
- 标准 env = **kv=1 速度伺服轮** (非扭矩) — 文献的异类, 天然不适合经典 LQR
- 扭矩版 (scene_flat_vmc.xml ±10N·m): 重力矩 38N·m/rad vs 轮 10N·m → 能抵消到 0.26rad, **权威够**
- 但**关节腿破坏了刚性 Segway 假设**: 用实测质量/惯量构建的精确 Segway 模型 (α=50, β=-2.15, δ=7.34), 其 δ(轮扭矩→加速) 与实测 (≈1) 差 7 倍 → 模型与真实耦合不匹配 → LQR 增益错误
- 即使腿 kp=5000 (近刚性) + 理论模型 → 仍 ~0.65s

## ★ 根本性结论 (已充分验证)

**xqrobotwl 的标准/扭矩作动器配置下, 两轮平衡无法由纯线性 LQR/MPC 在合理工程努力内稳定**:
- 轮子控制权威对倒立摆根本性不足 (kv=1 速度伺服 或 ±10N·m 扭矩)
- 关节腿的耦合/柔顺动态使刚性倒立摆线性模型严重失真 (模型权威参数与真实差数倍)
- RL 策略 (训练数千轮) 用协调腿+轮 + 非线性平滑控制才达到 15s
- **这正是项目用 RL 的原因** — 经典线性控制在这个软腿/弱轮机器人上不是调参能解决的

## 腿协助平衡路径 (用户选择) — 已测, 无效

- **RL 腿命令几乎恒定** (拟合 RMSE=0.03, 范围小) → 稳态平衡 RL 的腿基本不动, 腿不是平衡主力。
- **CoM 偏移协助** (hip_pitch 随倾角偏移 ±k) → 无改善 (~0.6s)。
- **从对称着地干净起点** (DEFAULT 腿 + base 0.475) → 1.27s (最好), 但仍失败。

## 最终失败机制 (精确诊断)

- t=0.4s: th=+0.13, **thd=+3.78**, tau=-10 (饱和) → 倾角快速增长, 轮扭矩饱和也无法抵消。
- **实测 β (扭矩→倾角) ≈ 0.5** — 是模型 (3-7) 的 1/6-1/10。轮扭矩 ±10N·m 只给 ~5 rad/s² 抵消, 而失稳 α·θ 在 θ=0.17 时达 5 rad/s² → 极限抵消角 ~0.17 rad, 任何扰动超出即不可恢复。
- RL 策略的 15s 来自: 协调腿+轮 + 非线性富 obs 平滑控制 (训练数千轮)。

## 最终诊断 (2026-08-14): 两个真实 bug + 权威不足定论

**用户持续追问驱动了深度排查, 找到并修复 2 个真实 bug**:
1. **轮子方向反了** (用户从视频发现): 前驱映射应为 左轮-τ/右轮+τ (镜像轴)。修复前轮子推反方向。**重大突破**。
2. **初始 base_z 偏高 → 轮子悬空**: 髋 pivot 在 base 原点下方 8mm, 我算的 base_z=0.526 让两轮浮空 3-9mm → 启动即砸地踢动。修正为 0.516 (双轮压地)。

**修复后仍失败 (0.8s), 定量确认权威不足**:
- 方向测试 (正确 base_z): 前倾+后驱(τ=-5) Δ+0.057 vs 无控制 +0.164 → **后驱是正确方向**
- 但闭环中控制器命令到饱和(-10)仍不够 → 轮扭矩 ±10 N·m 物理上不足以抵消 38 N·m/rad 重力矩的动力学需求
- 前倒/后倒监控: 轮子都朝正确方向转 (前倒向前转~0.5m/s, 后倒向后转~1.2m/s), 但轮面速追不上倒下的机身 (权威/摩擦限制)

**最终结论**: 这台机器人轮扭矩权威 (±10 N·m) 对 18.65kg 高重心是物理性不足的, 线性 LQR/MPC 无法实现干净平衡; RL 策略 (协调腿±50N·m + 非线性控制) 是唯一能平衡的。这验证了学习控制在此类机器人上的必要性。
