# 跳跃完整评估：逐阶段姿态监控 + 达标判定

**日期**: 2026-08-15
**评估工具**: `tools/xqrobotwl/eval_jump_full.py` (新建, commit cf2d182) — 按 CLAUDE.md §7.5 + §1.3 姿态表格
**数据**: `logs/pose_data/*_jump_full.csv` (每步 6 关节 + base 欧拉 + up_z + 轮速 + 轮接触 + phase)
**对象**: 纯PPO / PPO+VMC 的 08-14 基线 vs 今日改进版 (纯PPO v7 model_3999, PPO+VMC v3 model_3999)

---

## 1. 评估方法 (六阶段全链路)

一次跳跃周期触发序列: 站立80步 → 触发ON 160步 → 恢复200步。逐阶段监控:

| 阶段 | 监控项 (数据列) |
|---|---|
| ① 站立 | base_z≈0.52, up_z>0.85, \|gyro\|<1, 左右对称, 轮着地 |
| ② 触发→下蹲蓄力 | base_z 降, 膝屈曲 (\|knee\|↑), hip 前摆 |
| ③ 起跳 | 轮离地瞬间, 起跳前蹬伸 (膝伸直) |
| ④ 空中 | 腾空步数, 峰值跳高, up_z (直立), 空中转轮 |
| ⑤ 落地 | 冲击速度, 落地缓冲 (最低 z), 落地轮速匹配 |
| ⑥ 恢复站立 | base_z/up_z/稳定 (|gyro|), 前后/左右对称 |

姿态分类按 §1.3 表格: 正常站立 / 下蹲 / 伸腿 / 前倾 / 后倾 / 左右倾斜 / 左右高低腿 / 髋外展 / 摇摆。

## 4. 结论

### 改进成果 (vs 基线)
1. **纯PPO**: 火箭 (0/7, 第5步崩) → **受控小跳 (5/7, 100% 恢复站立)**。站立干净 (up_z 0.999),
   空中直立 (up_z 0.997), 落地温和。**成功率达标 §7.5 ≥90%**。
2. **PPO+VMC**: 基线跳得高但姿态差 (空中前倾/转轮16rad/s/站立摇摆) → 改进版更直立干净
   (up_z 0.997, 收腿轮速5.7, 落地不空转), 但跳高降 (0.233→0.156m) 且下蹲不足。

### 共同瓶颈 (两个算法的改进版)
1. **下蹲蓄力不足** ⚠️: 膝屈 0.04 rad, base_z 只降到 0.50 — 没有真正下蹲蓄力,
   直接从站立位蹬伸 → 跳高卡在 0.11-0.16m (< 0.20 阈值)。
2. **恢复站立晃动** ⚠️: 恢复期 |gyro| 1.9-2.6 (>1 阈值), 左右高低腿 — 落地后未完全稳定。
3. **起跳蹬伸不充分**: 起跳前膝未伸直 (|knee| 0.4-0.5), 蹬伸无力。

### 纯PPO 的固有平台
纯PPO 经 5 轮迭代 (v3-v7) 收敛到"受控小跳 + 100% 恢复"的稳定平台, 但**无法学会深蹲蓄力
→ 跳高卡 0.12m**。根因: 无 SLIP-FSM 参考结构, 策略发现"小跳+落地恢复"是最高性价比解
(深蹲→高跳的风险/努力 > 收益)。与 SRL (0.59m) / 项目结论 "纯PPO 无参考只能学到不可控
小跳" 一致 — 现为"受控小跳"。

## 5. 下一步建议

1. **提高下蹲蓄力**: 对两算法加强 crouch_depth / 深蹲门控, 或 (PPO+VMC) 强化 FSM crouch
   参考的力矩使能 (crouch_length 0.28 未被策略执行到位)。
2. **恢复稳定**: 加强 landing_recovery 权重 / 恢复期 anti_drift, 压 |gyro| 到 <1。
3. **渲染视频**: 修复 `render_jump_repeat.py` 的 env.reset API 兼容, 输出逐阶段视频给老板观察。
4. **纯PPO 是否继续**: 若接受"受控小跳"即为达标 (成功率100%, 高度稍低), 可定稿; 若要求
   高度 >0.20m, 需加参考结构 (退化为 SRL) 或更强深蹲强迫。
