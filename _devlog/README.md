# XqRobotV2 开发日志 (DevLog)

闭环开发记录系统。每一次改动、评估、修复都须记录，形成"问题→分析→方案→修改→评估→结论"的完整链路。

## 目录结构

```
_devlog/
├── README.md                   # 本文件（规范说明）
├── TEMPLATE.md                 # 日志模板
├── INDEX.md                    # 全局索引（按时间线）
│
├── <task>/                     # 按任务分类
│   └── <algo>/                 # 按算法分类
│       ├── INDEX.md            # 该组合的开发记录索引
│       └── <YYYY-MM-DD>/       # 按日期分目录
│           └── <序号>_<标题>.md  # 单条日志
│
├── assess/                     # 评估框架本身的开发日志
│   └── ...
```

## 日志命名规范

```
_devlog/<task>/<algo>/<YYYY-MM-DD>/<序号>_<英文slug>.md
```

示例：
```
_devlog/flat_walk/ppo/2026-07-01/01_fix_hip_asymmetry.md
_devlog/assess/2026-07-01/01_build_framework.md
```

序号为当天顺序，从 01 开始。

## 日志内容要求

每篇日志**必须**包含以下章节（缺失视为不合格）：

| 章节 | 必填 | 内容 |
|------|------|------|
| **日期** | ✅ | YYYY-MM-DD |
| **来源** | ✅ | 触发原因（训练评估 / 代码审查 / 测试发现 / 论文参考） |
| **问题描述** | ✅ | 具体现象、数据指标、错误日志 |
| **根因分析** | ✅ | 为什么会发生，影响范围 |
| **解决方案** | ✅ | 具体修改内容 |
| **修改文件** | ✅ | 绝对路径 + 行号 + 改动内容摘要 |
| **验证方法** | ✅ | 如何确认修复有效 |
| **评估结果** | 条件 | 若涉及策略修改，必须附 assess 评估数据 |
| **后续计划** | ✅ | 遗留问题、下一步方向 |
| **关联日志** | 条件 | 链接到相关的前序/后续日志 |

## AI 开发纪律

**所有通过 AI (opencode) 进行的开发活动都必须自记录：**

1. 每次修改代码文件 → 写日志
2. 每次调整超参数 → 写日志
3. 每次评估得出新结论 → 写日志
4. 每次修复 bug → 写日志
5. 每次架构变更 → 写日志

AI 在完成用户指令后，应**主动**判断是否需要写日志，并提示用户确认。对于明确涉及代码/配置更改的操作，**必须**写入日志。
