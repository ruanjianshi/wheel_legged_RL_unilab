# SRL+VMC v8e5: 消灭"下蹲相提前升起"双重运动 (跳跃不干净)

**日期**: 2026-08-17
**来源**: 负责人看 final10000 高度曲线/视频, 反馈"SRL+VMC 跳跃不干净"。

## 诊断 (验证评估)

复现验证 (3/3 次一致) — SRL+VMC final10000 轨迹存在**迟疑/双重运动**:

```
下蹲到位 (z≈0.33) → 提前升起 (z≈0.62) → 回落 (z≈0.52) → 才真正起跳 (z≈0.75)
```

对比 SRL (关节 PD): 下蹲 (z→0.39) → 单次爆炸蹬伸 (vz→+2.68) → 到顶, **单次干净运动**。

**根因**: 下蹲相 (FSM=0, 0.5s) 里策略把 L0 残差顶起来 → 提前上升。
`vertical_thrust` (jump_phase≥12 即奖 vz>0) 和 `height_progress` 都奖励了这个
提前上升 → 策略学会"下蹲相白拿奖励", 又被 FSM 蹲姿参考 (L0_ref=0.24) 拉回,
形成双重运动。

控制层测试 (无需重训): 下蹲相清零 L0 残差 → 轨迹变干净但跳高降 (0.668 vs 0.704),
因为破坏了策略的整体下蹲策略。

## 修改了什么 (v8e5, 奖励层修复)

`jump_srl_vmc.py`:
1. **`_reward_vertical_thrust`**: 门控到 **FSM state≥1** (蹬伸相及之后) 才奖励 vz>0。
2. **`_reward_height_progress`**: 同上。

下蹲相 (FSM=0) 两个奖励都不发 → 策略无动机提前升起 → 蹲稳 → FSM 进蹬伸 → 单次
干净起跳。

## 验证方法

- pytest 10 passed
- 10000 iter 重训 (GPU1, run_suffix=v8e5_10000, `logs/train/jump_srl_vmc_v8e5.log`)
- 目标: 轨迹单峰 (无提前升→回落→再跳), 跳高保持 ~0.25m

## 训练后效果 (model_9999, 达标 ✅)

**修复成功 + 跳高大幅提升**:

| 指标 | final10000 (v8e4) | **v8e5** |
|---|---|---|
| 轨迹形状 | 双重运动 (提前升→回落→再跳) | **单峰干净** (3/3 复现) |
| 跳高 (轨迹) | 0.225±0.038m | **0.306–0.316m** |
| 跳高 (eval_jump_full) | 0.229–0.266m | **0.356m** |
| 空中 up_z | 0.992–0.996 | **0.996** |
| 恢复 \|gyro\| | 0.52 | **0.63** |
| 达标 | 7/7 | **7/7** |
| 重复成功率 | 100% (20/20) | 85% (18/20 真跳, 17/20 恢复) |

**为何跳高更高**: 门控去掉了下蹲相白拿奖励的动机 → 策略蹲更深 (z 0.31, 更接近
l0_min) → FSM 进蹬伸时单次爆发蹬伸 (不再中途回落浪费动量) → 更高跳。

**重复成功率 100%→85% 的原因**: 跳得更高 (均值 0.308, 最高 0.505m) → 高跳落地
冲击更大 → 3/20 高跳落地失败。这是"更高跳"与"落地稳定"的固有张力。
