## 问题描述

基线 model_999 (1000 iter) 验证为好的后空翻策略后, 续训到 5999 iter (v2 run)。训练日志显示 flip_complete 0.31-1.0, mean_reward 66-77, ep_len 558-633 —— 看似更好。但**确定性评估全部 checkpoint** 发现:

| checkpoint | flip_complete | up_z 最低 | max\|a\| |
|-----------|--------------|----------|---------|
| 基线 model_999 | **96** | **-1.00** | **0.39** |
| v2 model_2000 | 0 | +0.50 | 0.86 |
| v2 model_3000 | 0 | +0.62 | 2.14 |
| v2 model_4000 | 0 | +0.86 | 2.84 |
| v2 model_5998 | 0 | +0.85 | 2.69 |

## 根因分析

1. **训练日志指标是 on-policy 随机采样下的均值**, 包含探索噪声和 ff 驱动的翻转; 确定性评估 (取策略均值动作) 才反映真实行为。
2. **v2 策略逐渐学到用巨大动作把机器人"钉住"不翻转** (max|a| 0.39→2.84), 靠站姿奖励 (stand_balance/stand_height/alive) hack: 站姿 episode 长 (558-633), 总奖励高 (66-77), 但**不完成后空翻** (up_z 最低 +0.5, 只倾斜不到 60° 没翻过去)。
3. 触发因素: `clip_actions=100` 允许无界动作 (devlog 06 为平衡放宽), `action_magnitude=-0.02` 惩罚太弱, 挡不住站姿 hack。

## 解决方案

**模型选择: 采用基线 model_999 (1000 iter)。** 续训过 train 是负收益。

- 基线 model_999 是已验证的甜点位: 真后空翻 (up_z=-1.0), flip_complete 96 次, 动作干净 (max|a|=0.39)
- v2 续训暴露的风险: 一次性动作任务 + 宽松动作上限 → 长训练易收敛到"站姿 hack"
- 后续若要稳健性, 应从 model_999 出发**加约束** (收紧动作上限 / 加强 action_magnitude / 域随机化), 而不是裸续训

## 修改文件

无 (纯实验结论, 配置保持基线权重)

## 验证方法

确定性评估全部 checkpoint (64 env, 500 步): flip_complete / up_z 最低 / max|a|

## 评估结果

- 基线 model_999 = 当前最佳后空翻模型 (flip_complete 96, up_z -1.0, 动作干净)
- v2 5999 iter = 发散 (动作爆炸, 不翻转)
