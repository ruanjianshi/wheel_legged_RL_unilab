# 13 — v5 窗级交替考核状态机: 彻底消灭"单侧抬/弯膝刷分"捷径

## 日期
2026-08-18

## 来源
v4 训练 (2026-08-18_12-21-52) 中途曲线揭示:
- phase_knee_lift **2.79** (scale 20 → 55.9/步, 策略疯狂深弯膝) 但 swing_lift **0.0000** (轮从未离地)
- swing_contact_penalty 恒定 -26 (摆动窗内着地罚 30)

## 根因分析 (三层, 逐步排除)

| 版本 | 现象 | 根因 |
|------|------|------|
| v2 (30/5 逐时) | 抬腿能学但 ep_len 崩 10 | 抬腿动作撞紧关节终止阈值单帧误杀 → v3 放宽+延迟终止 |
| v3 (60/10 逐时) | 抬腿涌现但**单侧化** (L4.5/R0.5) | 逐时奖励经济性: 单侧抬照样拿摆动窗大半奖, 免受另一侧窗罚 |
| v4 (30/30 逐时) | 罚重后**不抬腿, 深弯膝刷分** | phase_knee_lift 与轮离地无耦合 — 弯膝 55.9/步 > 摆动窗罚 30/步 → "弯膝刷分"局部最优 |

**核心缺陷**: 逐时刻奖励无法考核"轮在摆动窗内离地"这一周期级事件; 且单侧惩罚与探索动力无法两全。

## 修改了什么 (v5)

**窗级交替考核状态机** (toe_walk_mode.py `_update_lift_windows`):
- 摆动窗 = 相位 sin>0.2 (L) / sin<-0.2 (R); **窗结束才结算**
- 结算规则:
  - 本窗曾离地 且 上一结算窗也离地 (交替链完整) → 奖 `window_lift`(30) × 窗内离地占比
  - 本窗离地但链断 → 半奖 (恢复机制)
  - 本窗从未离地 → 罚 `window_penalty`(150) 一次
- **phase_knee_lift 门控**: 当前摆动窗已离地才计分 (消灭弯膝刷分)
- 经济性: 双侧交替每周期 +60; 单侧抬 30-150=**-120 (亏损)**; 不抬 -300
- 取代: phase_swing_lift / swing_contact_penalty (conf 移除)

conf 变化: 新增 window_lift 30.0 / window_penalty 150.0; phase_knee_lift 15.0 (门控后); 移除 phase_swing_lift/swing_contact_penalty。

附注: 本轮遇到 GPU 显存不足 (系统 ollama LLM 服务占用 GPU1 22.7GB, 不可杀), v5 训练降为 **512 envs** (显存 ~1.2GB 即可), ETA ~1.5h; 能力验证通过后若 GPU 空闲再恢复 1024 复训。

## 预期效果
1. 双侧交替成为唯一有利解 (单侧净亏 120/周期)
2. 弯膝只在离地后有分 → 深弯膝刷分路径关闭
3. 站立模式不受影响 (窗奖励 mode 门控 ×0)

## 验证方法
- Stage2 观察: window_lift >0 且 window_penalty 从高位下行, lift_sym 保持低 (双侧均衡)
- 训练后 `verify_toe_walk_mode.py`: 抬腿段 L/R 离地次数接近 (比值∈[0.5,2]) + 交替判定 + 站立 PASS + 切换稳定

## 后续计划
