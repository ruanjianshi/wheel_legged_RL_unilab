# 12 — v4 调整: 双侧抬腿经济性平衡 + 按模式区分终止严格度

## 日期
2026-08-18

## 来源
v3 训练 (2026-08-18_10-58-18) 最终评估 model_9999 暴露两个新问题。

## v3 结果与根因

| 评估项 | v3 model_9999 | 根因 |
|---|---|---|
| 站立模式 | ❌ linvel_xy 0.253 (>0.2), gyro **2.862** (>1), 高度 0.611m, 漂移 0.64m | v3 的"异常延迟 5 帧终止"对站立也宽容 → 歪斜能存活 → 策略放松 |
| 抬腿模式 | ⚠️ **L/R = 4.5/0.5 单侧抬** (v2/v3 训练数值爆表但行为单侧) | **奖励经济性失衡**: phase_swing_lift 60 vs swing_contact_penalty 10 — 单侧抬每周期净赚 (0.36×60)−(0.36×10)≈18, 双侧抬只多赚一份; 策略选单侧 |
| 转圈趋势 | avg_vy +0.17, gyro_z 1.86 | 单侧抬的推进不对称 → 持续转向 |
| 切换稳定 | ❌ | 站立段被前段抬腿惯性+宽松终止拖累 |

训练数值 vs 行为事实的教训: swing_lift 6.8~10.7 (训练均值) 可以由"多数 env 单侧抬"产生, 而 lift_symmetry EMA 是 L/R 总量差, 会被"不同 env 不同侧"在 batch 均值上抵消 → **对称性必须在单 env 内用"摆动相两侧都考核"实现, 而非总量 EMA**。

## 修改了什么 (v4)

| 文件 | 改动 |
|------|------|
| `mujoco.yaml` | `phase_swing_lift` 60→**30**, `swing_contact_penalty` 10→**30** — 双侧抬每周期净赚 21.6, 单侧抬净赚≈0 (摆动窗着地罚 ≥ 摆动窗离地奖) |
| `toe_walk_mode.py` | 终止延迟**按 mode 区分**: mode=0 站立立即终止 (达到苛刻), mode=1 抬腿延迟 5 帧 (宽容探索) |
| `verify_toe_walk_mode.py` | 站立段 3s→5s (切换后验证"刹住"更充分) |

## 预期效果
- 抬腿: 双侧交替成为唯一有利解 (单侧净赚 0)
- 站立: 恢复 v1/v2 的 PASS 水准 (立即终止压制歪斜)
- 转圈: 随双侧抬而消失

## 验证方法
- 训练中每 1k iter: swing_lift 与 lift_sym 曲线 + ep_len
- 训练后: verify_toe_walk_mode.py — 站立 PASS + L/R 离地次数接近 (比值 ∈[0.5,2]) + 交替/对称判定 + 切换稳定
